# LiuScope（柳镜）用户手册 · v1.2 新功能篇

适用版本 v1.2.x。基础收发与波形用法见 [README](../README.md)；AI 通道完整协议见 [AI_INTERFACE.md](../AI_INTERFACE.md)。
本手册只讲 v1.2 新增/重构的功能：设置页与主题、终端页新交互、波形页读数与导出、频谱导出口径、STM32 烧录页、AI 控制通道速用。

---

## 0. 快速上手（exe 用户，5 分钟）

1. 从 [Releases](https://github.com/TZH-user/liuscope/releases) 下载 `liuscope.exe` 与 `SHA256SUMS.txt`。
2. 校验（可选但推荐）：`certutil -hashfile liuscope.exe SHA256`，与 SHA256SUMS.txt 比对。
3. 双击运行。首次启动 SmartScreen 提示时点「更多信息 → 仍要运行」；杀软误报时校验哈希后加白名单。
4. 插入串口设备 → 终端页选 COM 口与波特率 → 连接。

**配置与数据**：配置在 `gui_settings_qt.ini`（与 exe 同目录），日志在 `logs\`（勾选「自动保存日志」后生成）。升级直接覆盖 exe，配置向前兼容；重置 = 删除该 ini。
**卸载**：删除 `liuscope.exe` + `gui_settings_qt.ini` + `logs\` 即可，不写注册表、无残留。

**故障排查**：

| 现象 | 处置 |
|---|---|
| 双击无反应 / 报缺 DLL | 安装 VC++ 运行库；看 `logs\` 与弹窗信息 |
| 首次启动慢（3~10 秒） | onefile 单文件自解压特性，非卡死 |
| 找不到 COM 口 | 装 CH340/CP210x 驱动；设备管理器确认 |
| 串口被占用 | 关闭其他占用程序（含另一个 LiuScope 实例） |
| STM32 页探测不到 ST-LINK | 设置页确认 CLI 路径；装 STM32CubeProgrammer 与 ST-LINK 驱动 |

## 1. 设置页与主题

入口：页签 **设置**。

- **主题**：深色 / 浅色 二选一下拉，切换立即生效（含所有页签、绘图区、右键菜单），重启后保持。
  - 已知限制：终端页**已落显的历史日志行**保留切换当时的配色，新行按新主题着色；点「清空记录」即可整体刷新。
- **曲线填充**：勾选后波形曲线下方填充半透明色。原波形页内的复选框已迁移至此，全局生效。
- **STM32 CLI 路径**：STM32CubeProgrammer 命令行完整路径。**留空 = 自动探测**（按 `X:\ST\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe` 模式扫描各盘符 + PATH）。装在非标准位置时在此手动指定。

## 2. 终端页新交互

- **连接按钮状态化**：未连接显示「连接」，已连接显示「断开」，连接丢失/打开失败自动回到正确状态，不再出现"已连接却还写着连接"的歧义。已连接时波特率下拉灰化，悬停提示「已连接：断开后才能修改」。
- **网络串口（v2 分支预览）**：端口下拉可直接手输 pyserial URL 后点连接——`rfc2217://192.168.1.50:7000`（板端跑 ser2net，波特率由板端协商执行；NPort 等串口服务器同协议）、`socket://IP:端口`（TCP 裸透传）。板端配置样例见 `server-rk/ser2net.yaml.example`。
- **聊天式对齐**：接收（RX）行靠左，发送（TX）行靠右，类似聊天软件；行的时间先后顺序不变，窗口拉宽后右对齐自动重排。
- **悬停互转**：鼠标停在任意日志行 0.4 秒弹出提示——HEX 接收模式下把该行解码为 文本(UTF-8)/十进制/float32(小端)；文本接收模式下给出该行的 HEX。悬停条目头行等效于悬停其正文行。
- **关键词高亮告警**：设置页「日志」区可配「错误关键词」「关注关键词」（逗号或空格分隔）——接收行命中错误词整行红色加粗、命中关注词整行琥珀色，大小写不敏感、立即生效
- **字号缩放**：日志区按住 Ctrl 滚动鼠标滚轮（或 Ctrl+= / Ctrl+- / Ctrl+0）缩放字号，重启保持
- **BREAK 与信号线**：日志行右侧新增 BREAK 按钮（发送串口 BREAK）；连接后 CTS/DSR/RI/CD 状态实时显示（●有效 ○无效）
- **多会话窗口**：顶行「新窗口」（Ctrl+N）再开一个独立会话窗——每窗可连不同串口，各有自己的日志/波形/频谱；发送行勾选「广播」可同时给多块板子发同一条命令（只发已连接的窗口）
- **序列发送**：底部「序列」按钮打开脚本发送器——`send 文本` / `sendhex 十六进制` / `delay 毫秒` 每行一条，# 为注释，支持重复次数、循环、连接后自动执行
- **协议文件发送**：「文件发送」旁下拉可选 原样 / XMODEM / YMODEM——YMODEM 适配 STM32 ROM bootloader 与 U-Boot loady 烧录（自动等对端 C 请求、完成/失败落日志）
- **正则查找**：查找条勾选 `.*` 后按正则表达式匹配日志（大小写不敏感）
- **窗口置顶 / 选中即复制 / 相对时间戳**：设置页「页面显示」与「日志」区开关
- **等宽字体与自动折行**：日志区用等宽字体显示（Windows 下为 Consolas，中文自动回落雅黑），字符画、框线图、HEX 列按终端网格对齐；接收/发送内容超出窗口宽度时自动折到下一行，拖动窗口大小即时重排，不再出现横向滚动条。
- **ANSI 终端渲染**（日志区开关，默认开）：串口回传里的 ANSI 颜色转义（SGR）按设备指定还原——鲁班猫等 Linux 串口控制台的绿色提示符、彩色 dmesg、框线 banner，以及 ESP-IDF 日志色码都会显示成设备本来的样子（16 色 / 256 色 / 真彩，粗体 / 斜体 / 下划线 / 删除线 / 反显 / 暗淡）。清屏、光标移动、窗口标题等对滚动日志无意义的序列自动剥除；空格保排版，框线图与 ASCII 艺术字不会散架；个别颜色对日志背景对比度过低时自动混色保底。条目原文与自动保存日志不受影响（始终记录原始字节解码结果，含转义码）。关掉开关即回到纯文本显示（转义码原样可见）。

## 3. 波形页：读数与导出

- **悬停读数**：在绘图区移动鼠标出现十字线与读数框——第一行是 x 坐标，随后**每条可见曲线一行「曲线名: y 值」**（与曲线同色），y 取该 x 处真实采样点。
- **「显示点数」**（原「窗口」改名）：横轴显示的帧数档位，与鼠标滚轮横轴缩放联动。
- **导出**：工具行「导出」按钮 →
  - **导出PNG**：当前时域绘图区单图渲染；
  - **导出CSV**：全量缓冲（含时间戳与全部通道）。
  - 绘图区**右键菜单**（全中文）：恢复自动缩放 / 导出PNG / 导出CSV / 显示网格。
- **XY 相位图**：工具行按钮开关。每窗口可独立选 X/Y 通道来源，量程 ±N 或自适应，窗口数 1/2/4，分格 4/5/8/10/16，点/线绘制，余晖 6 档。XY 数据同样出现在 AI 通道 `xy_snapshot` 里。

## 4. 频谱页：导出口径与清空

- **频率轴对齐**：谱图与瀑布图共用同一频率坐标（双向联动），同一频点上下垂直对齐，确认频点不再来回对轴。
- **导出PNG**：谱图 + 瀑布（勾选「瀑布」时）纵向拼图，顶部自动标注采样率 / FFT 点数 / 窗 / RBW / 通道等参数，截图即证据。
- **导出CSV**：对话框二选一：
  - **最新一帧瞬时频点**：只导当前帧的 频率/dB 两列；
  - **最近 N 秒**：导出最近 N 秒内全部帧。**N 的上限就是软件已累计采集的时长**——输入更大的值会被自动钳制到实际时长，不会导出不存在的数据。
  - 历史缓冲上限：6000 帧 或 2000 万单元格（先到为准），超限丢最旧；长时高频点采集时内存有界（约 80MB 封顶）。
- **清空**：轨迹 / 峰值保持 / 指数平均 / 瀑布 / 导出历史全部复位，采集时长清零。

## 5. STM32 页（STM32CubeProgrammer CLI）

入口：页签 **STM32**。本页通过 ST 官方 **STM32CubeProgrammer CLI** 驱动 ST-LINK，适合不切软件就能复位/烧录的联调循环。

### 5.1 前置安装

1. 从 ST 官网下载安装 **STM32CubeProgrammer**（默认路径如 `C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\` 或 `X:\ST\STM32CubeProgrammer\`）。
2. 打开 LiuScope **设置页**：CLI 路径留空即可自动探测；探测失败再手动指定 `STM32_Programmer_CLI.exe` 完整路径。
3. ST-LINK 驱动随 CubeProgrammer 安装；首次插拔建议用本页「刷新」确认枚举。

### 5.2 页面功能与按钮

| 按钮 | 行为 | 对应 CLI |
|---|---|---|
| 刷新 | 枚举 ST-LINK 探针列表（只读） | `-l` |
| 连接目标 / 断开 | 连接/断开 SWD 目标，显示 芯片型号/REV、SN、固件版本、电压 | `-c port=SWD mode=UR` |
| 软复位 / 硬复位 | 复位目标（软=系统复位，硬=NRST 板级复位） | `-rst` / `-hardRst` |
| 选择 hex/bin… / 烧录（带校验） | 烧录所选文件并自动校验：hex 走 `-d`（自带地址）；bin 走 `-w 文件 基址`（默认 0x08000000） | `-d/-w … -v` |
| 全片擦除 | 整片擦除（**毁灭性操作，慎点**） | `-e all` |
| 读保护解除 | 解除 RDP 读保护（会触发全片擦除，**毁灭性操作**） | `-rdu -y` |
| 读取 OB | 读取选项字节 | `-ob displ` |

所有命令行输出都实时回显在页面下方日志区（含 CLI 原文，便于排错）。

### 5.3 安全须知

- **烧录/全片擦除/读保护解除均不可逆**：确认所选文件与目标板正确后再操作。
- 本页只操作 **ST-LINK/SWD**，与串口页（CH340 等）互不影响，可同时使用。
- 连接状态下目标已暂停运行的场景（如低功耗），先「连接目标」再执行复位即可恢复运行。

## 6. AI 控制通道速用

GUI 启动即自动监听 `tcp://127.0.0.1:9101`（默认开启，菜单可一键复制接入信息）。一行 JSON 请求，回一行 JSON 响应。完整命令表（19 条）、follow 连续输出、无头捕获模式见 [AI_INTERFACE.md](../AI_INTERFACE.md)；随时可发 `{"cmd":"help"}` 拿同源命令表。

最快上手三条：

```jsonc
{"cmd":"status"}                         // 连接/协议/帧数/录制状态快照
{"cmd":"send","text":"INFO\r","newline":"LF"}     // 让 AI 代发一条串口命令
{"cmd":"read_lines","count":20,"filter":"ERR"}    // 按正则回读最近记录
```

三件 v1.2 重点能力：

- **数据快照**：`wave_snapshot` / `spectrum_snapshot` / `xy_snapshot` / `modbus_recent` / `stm32_status` —— AI 无需碰 UI 就能拿到波形数值、频点+dB（含主频与参数）、XY 轨迹、Modbus 事务、ST-LINK 状态。
- **连续输出**：`read_lines` 带 `follow:true` 进入持续推送（`interval` 节流、`max_lines` 上限、`filter` 过滤），发 `stop` 或直接断开退出。
- **控制与 UI 同步**：`settings_set` 改波特率/协议/显示点数/主题等，**GUI 前端同步跟随**（下拉框、按钮、页面主题真的会变），并返回改前/改后值；支持中文别名键（如 `"key":"显示点数"`）。

> 无头捕获（AI 独占串口、JSONL 输出、触发/期望/回放）见 AI_INTERFACE.md 第 2 节，适合 CI 与自动化闭环。

## 7. v1.3.0 新增：ESP32 联调

### 7.1 打开串口不复位（第一痛点）
ESP32 的自动下载电路把 DTR/RTS 两根线映射到 IO0/EN。普通串口工具打开端口时会拉线 → 板子直接复位。柳镜的做法：
- 设置页 → 连接（ESP32）→ 勾选「**打开串口时不拉 DTR/RTS（ESP32 防复位）**」，之后每次连接都会在打开后立即松开两根线
- 不勾选时行为与普通工具一致（部分场景反而需要打开即复位）

### 7.2 设备线控（复位 / 下载模式 / DTR / RTS）
连接成功后，日志区右下角出现四个按钮：
| 按钮 | 作用 | 说明 |
|---|---|---|
| 复位 | EN 拉低再放开 | 等同按板上的 RST 键，重新运行用户程序 |
| 下载模式 | esptool 经典时序 | 复位期间拉低 IO0，进 ROM bootloader（之后即可用 esptool/IDF 烧录） |
| DTR / RTS | 实时拉高/松开 | 手动控制两根线，调试自定义下载电路用 |

按钮未连接时置灰；对 `loop://` 等虚拟端口点击会提示「不支持线控」。
**注意**：ESP32-S2/S3/C3 的内置 USB-Serial/JTAG 口没有经典复位时序，请用外挂 UART 口（CP210x/CH340）配合这组按钮。

### 7.3 ESP-IDF 日志解析
日志区勾选「ESP-IDF 日志解析」（默认开）后：
- `I (2812) wifi: …` 按等级着色：E 红 / W 琥珀 / D·V 暗灰
- 复位横幅 `rst:0x1 (POWERON_RESET)` 前插「── 设备复位: 0x01 POWERON_RESET ──」装饰行——**看门狗反复复位一眼可见**
- `Guru Meditation Error` panic 行红色加粗
- 日志区同时开着「ANSI 渲染」时，设备自带的 SGR 色码优先于上面的等级着色（以设备本来的颜色为准）；复位横幅装饰行、backtrace 收集不受影响

### 7.4 解析 backtrace（崩溃定位到源码行）
panic 之后的 `backtrace:0x400814ad:…` 行会被自动收集 pc 地址，「解析 backtrace」按钮点亮：
1. 点击 → 对话框里选工程 ELF（`idf.py build` 产物，如 `build/xxx.elf`）
2. addr2line 自动探测（IDF 工具链 `xtensa-esp32-elf-addr2line` 等；找不到可手动选）
3. 「解析」→ 输出 `函数名 @ 文件:行`，直接定位崩溃点

ELF 路径、addr2line 路径、芯片型号都会记忆。

### 7.5 其他
- 端口下拉会标注芯片：CP210x / CH340 / CH341 / FT232 / **ESP32 JTAG**（内置口，无经典 DTR/RTS 时序，不适合高频二进制流）/ ESP32-S2 CDC
- 波特率预设补 74880（ROM 启动日志）、921600 / 2000000（烧录口）
- 波形页的 JustFloat / FireWater 即 VOFA+ 生态协议，ESP32 端用现成组件发帧即可直接出曲线

设置页 → 主题 → **自定义**：

### 8.2 页面显示
设置页 → 页面显示：可关闭「STM32 页」「Linux 支持页」页签（不用的生态收起来），设置记忆保持；取消勾选即恢复显示。

### 8.3 Linux 支持页（原设备屏）
经网线/UDP 接收 Linux 板卡（如鲁班猫）回传的 H.264 屏幕流并渲染；同时端口框支持 `rfc2217://` / `socket://` 网络串口直连。该页可在设置页隐藏。

**桌面回传用法（一键触发）**：
1. 板端先跑守护：`cd /home/cat && sudo -n env PYTHONPATH=/home/cat nohup python3 -m server_rk --verbose > /home/cat/server_rk.log 2>&1 &`
2. 页上确认「板 IP」（默认 192.168.2.100）、「控制」端口（9201）与「配对码」（默认 246810，须与板端一致）
3. 点「开始接收」：自动经控制通道配对并请求板端发流，状态行依次显示 已连接→已发流→帧率；点「停止」自动通知板端停流
4. 板端没跑守护时状态行提示「控制通道不可达」，此时仍可被动收流（等手工触发）

链路自适应：采集 kmsgrab→x11grab、编码 h264_rkmpp→h264_v4l2m2m→libx264（软编钳 12fps 防延迟积压），全在板端自动探测，PC 端无感。

**实时性证明（跑表 + 传输时延）**：发流成功后画面左上角有板端烙进视频的毫秒跑表（起流归零、按真实速度跳动——表在走就证明画面是"现在"采的，不是冻结/缓存；板端 drawtext 探测失败时状态行会注明 overlay=off）；统计行「传输≈x ms」为逐帧单向传输时延估算（板端发包时刻 vs PC 收到时刻，钟差自动校准，板子没校时也能用；局域网正常应在几十 ms 内）。若画面不居中/偏小，属于旧版本在高 DPI 屏的渲染缺陷，本版已修（等比缩放、居中满幅）。

**跑表开关与透明度**：工具行「跑表」复选框可关掉烙在画面里的毫秒表，「透明度」（10%~100%）可把它调淡到不挡内容；改动会保存并在发流中自动重起流生效（约 1~2s 空窗）。

**鼠标控制**：勾选「鼠标控制」后，鼠标在本画面上的动作直接注入板端——左/右/中键点击、按住拖动、滚轮滚动全部生效，画面里的板端光标跟着 PC 鼠标走（绝对坐标、自动换算缩放与黑边，指哪打哪）。要求：开始接收时填了板 IP（控制通道在会话中）；板端 server_rk 以 root 运行（/dev/uinput 与 X 会话）。不用时取消勾选即可，纯观看零注入。

**系统状态（1Hz）**：勾选「系统状态」后，页面底部实时显示板端 CPU 占用、内存、eMMC 容量与设备号、温度、负载与运行时长（1 秒一拍，独立于发流的小连接——不看画面也能看板况）。要求板端 server_rk 在跑；连接断开自动每 3 秒重试。首拍个别字段显示「--」属正常（占用/速率按两次采样的差值计算，第二拍起就有值）。

### 8.4 断线自动重连
设置页 → 连接（ESP32）→「断线自动重连」：串口异常后不立刻断开，后台每 2 秒按原参数重试；设备重插、烧录后 COM 重枚举都会自动接回（状态栏显示「等待自动重连…」→「已重连」）。
